## 列挙の契約と実装

`nbest_tokens(tokens, lex, k=8) -> (list[DecodeResult], stats)` を維持する。
`DecodeResult` の表記・読み・スコア・トークン区間つき `Piece` を返し、
`stats` の `ms/n_tokens/nbest` は維持、探索量の `n_pops` を追加した。
各表記につき最安経路を1件返し、スコアの非減少順を保証する。同点内は決定的な探索順。
要求したk件、または対象となる全表記を列挙した時点で終了する。
`k <= 0` は空リスト。入力が空なら、kが正のとき空表記・コスト0の1件を返す。

旧方式は途中を読みprefixで枝刈りし、終端に残った状態ごとに1経路だけ復元していた。
途中の同音語・分かち書き・左右の分岐が同じ終端へ合流すると候補に届かなかった。
新方式は以下を行う。

1. `_spans_from` の語アークを用い、前向きの厳密Viterbiで各位置・RIDの最小コストを計算。
   `POS_KEEP` や読みprefixによる打ち切りを入れない。最小値への統合はこの下界計算だけで、
   その位置へ至る語アークはすべて保持する。
2. 各位置・次語LIDについて、`最安prefix + 次語への連接` を保存する。
   これは次語自身の語コストを除いた、後ろ向き探索に対する厳密な残りコスト。
3. EOSから後ろ向きA*。ヒープの優先度を `suffixのコスト + 上記prefixの下界` とし、
   BOSへ到達したときに完成した表記を出す。後ろ側の語列はリンクとして保持し、
   完成時に読みとPieceを復元する。
4. 同じ `(開始位置, 先頭LID, suffix表記)` は最安suffixだけを残す。
   その状態へ接続できるprefixと接続コストは同じなので、高い同表記経路を捨てても
   distinct-surface k-bestは変わらない。読みが異なる同表記も最安経路の読みを返す。

入力位置が必ず進むDAGなので、負の語コスト・連接コストがあっても前向き最小値は厳密。
完成経路のヒープ優先度は実コストになり、未展開経路の下界を越えて完成候補を先に出さない。
このため候補順を保証できる。スコア幅・ヒープpop数・候補数の内部上限は設けていない。
参照E5の `margin=6000 / max_pops=20000` による途中打ち切りも採用しない。
大きなkや多分岐の入力では探索量・メモリが増える。今回LM推論・実機遅延の最適化は行わない。

従来のn-bestの出力条件を保ち、未知補完アークと語コスト `>= UNK_COST` のPieceは除く。
旧方式で完成後に除いていたものを先に除き、表示できない経路が探索を占めるのを避ける。
このため保証するのは**この出力条件を満たす経路集合内**での真のk-best。
対象経路がなければ空リストを返す。かな候補の脱出口は既存の文節候補側に残る。

リテラル面・明示リテラルは既存のBOS/EOS境界コストを使う。
空区間・連続リテラルはBOS→BOSを加算しない。実辞書のPOS=0と区別するため、
境界には既存の `BOUNDARY_RID=-1` を使う。
RID枝刈りの `decode_tokens`、`_spans_from`、`_prune`、既存の連接ヘルパーは変更していない。
FSM・辞書・連接行列・語コストにも変更はない。

## Stage 4の学習との関係

**n-bestは学習なしを維持した。** 既存シグネチャに学習・左文脈の引数はなく、
[STAGE4.md](STAGE4.md) でもオフラインn-bestは学習を参照しない契約としている。
暗黙にローカル学習ファイルを読むと、同じ辞書・入力で評価が再現できなくなる。

現在の `session.py` は `nbest_tokens` を呼ばず、`decode_tokens(..., learning=...)` と
文節候補のA*へ明示的に学習スナップショットを渡している。そこは維持し、
既存の1-best・文節候補の学習ボーナス・未知かな登録を壊さない。
将来n-bestにも左隣表記に依存するボーナスを入れるなら、POSだけの前向き状態では足りず、
同一suffixの統合条件も再検討が要る。今回は引数の追加や暗黙の学習適用をしない。

## 検証

単体＋トランスクリプトは77/77 PASS（既存71件は変更せず、追加6件）。追加分は以下を固定する。

- 同RIDへ合流する途中の別候補、12件を超えるRIDの保持、6000を超えるスコア差でも列挙する。
- 小さな全格子の総当たりと、全表記の最小スコア・順序・読みを照合する。
  負コスト、複数の分かち方、同表記の別経路・別読み、実POS=0、連続リテラル、混合面を含む。
  固定seedで30個のランダム格子も照合する。
- 1/3/8/30件の取得が全列挙のprefixに一致し、Pieceの区間・読み・表記を保つ。
- 未知補完・高コストの出力条件、空入力・非正のk、区間oracleと文全体の順位の違い、
  文候補のコスト和によるマージと表記重複除去。

回帰ゲートは5/5 PASS。既読/記憶と既読にない/記憶にないが上位8に共存し、
どうぞの上位8に王族・翁は出ない。`decode_tokens` と共有ヘルパーのASTが開始HEADと
一致すること、およびMozcの全594件で1-best表記が前後一致することを確認した。

| --- | --- | --- |
| 読み一致 | 92.4%（549/594） | 92.4%（549/594） |
