## 使い方・消去

既定の保存先はリポジトリ内の **`data/learning.jsonl`**。
ファイルが無ければ学習の読み込み・記録とも無効で、自動作成しない。
最初に空ファイルを作ると有効になる。学習データはgit対象外。

```sh
# リポジトリ直下 / Linux
(umask 077; touch data/learning.jsonl)
python3 -m oyayubi.ime.server

# 全消去。以後の記録も停止する
rm data/learning.jsonl
```

```powershell
# リポジトリ直下 / Windows PowerShell
New-Item -ItemType File .\data\learning.jsonl
python -m oyayubi.ime.server

# 全消去。以後の記録も停止する
Remove-Item .\data\learning.jsonl
```

別の場所を使う場合は `--learning-file /path/to/history.jsonl`。
その場合も先にファイルを用意する。`--no-learning` はファイルの有無にかかわらず
読み込み・記録を無効にする。Pythonからは `ImeSession(learning_path=None)`。
試験窓の `ImeSession.load()` も既定の保存先を使う。

削除は起動中のセッションでも次の表示更新・候補生成で検知し、学習経路と自動登録語を外す。
変換中に既に選択した表示は保持するため、それも直ちに捨てたい場合はEscかresetを使う。
追記は `O_CREAT` なしで開き、削除後の確定でファイルを再作成しない。
全プロセスを終了してから削除すれば、操作と同時に進行中だった確定も含めて確実に停止できる。
再開する場合は空ファイルをもう一度作る。手書きの `data/user_lexicon.jsonl` は消さない。

## 記録と保存形式

Enterと「変換中に次の文字を打つ」自動確定の両方で、選択中の各文節を
UTF-8 JSONLへ1行ずつ追記する。候補を開く・巡回するだけでは学習しない。
Esc・BSによる変換取消、未確定のresetも学習しない。

```json
{"reading":"こうせいを","surface":"校正を","left":"機関の","timestamp":1800000000.0,"cost":6305,"lid":1841,"rid":379,"user_word":false,"version":1}
```

上記の数値は形式を説明する例。`reading/surface/left` はそれぞれ文節全体の読み・表記・
直前の文節の表記。`timestamp` はUnix秒。`cost` は**学習ボーナスと両隣への連接を含まない**
文節内部の素のコストで、内部の複数語間の連接は含む。`lid/rid` はその文節の両端POS。
`user_word` はかな確定からの自動登録を示す。`version` は保存形式の版。

例えば「機関の校正をした」は「機関の／校正を／した」の3行を記録し、
「校正を」の左隣は「機関の」。リテラル自体は記録せず、次の文節の左隣にはその表記を使う。
compositionの先頭では直前に確定した最後の区間を左隣として引き継ぐ。
セッション開始・フォーカス喪失等のresetでは空文字に戻す。
外部アプリの周辺テキスト取得やキャレット移動の追跡は行わない。

JSONLを選んだ理由は、日本語・改行・引用符をエスケープして1行に保存でき、標準ライブラリだけで
読めて、ファイル削除で全消去できるため。本文・読み・時刻を含む**ローカルの平文**である。
自動送信はしない。起動時と変更検知時に読み直し、メモリ上では同じ3項組の最新記録にまとめる。
同じタイムスタンプではJSONLの後の行を最新とする。仮想経路の素のコスト・両端POSを
（読み, 表記）から選ぶ際もこの規則を使う。
複数セッションからの確定は次の更新で共有される。ディスク上は履歴を残す追記方式で、
現段階では自動圧縮・件数上限を設けない。長期間の増大が問題になれば圧縮を追加する。
不正行・途中で切れた最終行・未知の形式版は無視し、次の追記を別行にする。
入出力エラーで確定文字列を失わないようにし、エラーの型は `LearningStore.error` に残す。

## ボーナスと減衰の判断

学習点は素の辞書・連接コストから別に引く。記録rの重みを
`w(r) = 2 ** (-max(0, 現在時刻 - r.timestamp) / (30日))` とする。

| 一致 | 減算値 |
| --- | --- |
| 同じ（読み, 表記） | `2400 × その組の最新記録の重み` |
| 左隣の表記も一致 | 上に加えて `3600 × その3項組の最新記録の重み` |

合計を整数へ丸める。直後は通常一致2400、同じ左文脈なら6000、30日後にはそれぞれ半分。
文脈一致には空文字同士のBOSも含む。時計が戻っても6000を超えない。
頻度を足し上げず最新値を使うため、同じものを100回確定してもボーナスは増えない。
自動確定の反復で古い選択が無制限に強くなり、新しい修正を押し潰すことを避ける。
最新の別文脈での使用は通常一致の部分だけを更新する。
遅延列挙中に日付やファイルが変わっても順序が壊れないよう、1回の変換・候補生成では
学習内容と現在時刻のスナップショットを固定する。

2400は既存の「こうせい」BOS/EOSでの構成4632・校正6273（差1641）を上回る値。
同音語の修正が次回に効く一方で、未知1文字のペナルティ12000より十分小さい。
文脈一致の6000は既存の文節候補コスト幅6000に対応する強さとし、
異なる左文脈への通常ボーナスを抑えながら、その文脈での修正を優先させる。
半減期30日はドッグフード1週目の修正を1週間後も約85%残し、数か月使わない選択は弱める
初期の工学的設定であり、実測で最適化した確率モデルではない。
日単位で切れる方式より滑らかで、確定回数による減衰より入力頻度に左右されにくい。

## 未知語・1-best・文節候補への適用

学習は手書き `user_lexicon` と分けた**学習専用ファイル**に統合する。
かな候補の（読み, 表記）が既存辞書・手書きユーザー辞書に無ければ、
`user_word=true`、一般名詞の両端POS（1851）、素のコスト6000で自動登録する。
ひらがな・カタカナのどちらも、その候補のひらがな読みで登録する。
6000は未知1文字コスト12000の半分。手書き辞書の1800–3000程度より控えめにし、
最近の使用に対する優遇を別の学習ボーナスで与える。既存語ならその語の素のコスト・POSを使う。
未知かどうかは読み・表記の完全な辞書エントリの有無で判定するため、
短い辞書語の組合せで偶然出せる表記も単独のユーザー語として登録できる。

手書き辞書へ追記しない理由は、手で調整したコストを保ち、自動登録語と使用履歴を
**1ファイルの削除で一緒に消せる**ようにするため。学習ファイル中の自動登録語は
ボーナスが減衰しても辞書候補としては残り、削除すると取り除かれる。

確定した既知の文節も、内部コストと両端POSを保った仮想の追加経路として格子へ載せる。
「校正を」のような複数語にまたがる学習を辞書の単語単位へ分解して失わないためである。
学習した長い未知語は、通常辞書の16トークン上限とは別のprefix探索で扱う。
リテラル面を読みとして通したり、リテラル境界を跨いだりしない。

- **1-best**: 仮想経路を通る際に、その時点の左文節表記を使ったボーナスを引く。
  元の辞書経路も残す。確定内容を再学習しても素のコストへボーナスを焼き込まない。
- **文節候補**: 完成した区間全体の（読み, 表記, 左隣）へボーナスを適用してコスト順にする。
  A*の未完成経路には最大ボーナス6000を引いた下限を使い、完成時に実際の値へ戻す。
  最良の辞書候補からの幅6000を維持し、かな候補は従来どおり末尾に残す。
  左隣の表記や学習内容が変わった場合は候補を作り直す。

FSM・1-bestのRID枝刈り・評価用nbestの読みprefix枝刈り・辞書そのもののコストは変更していない。
1-bestは従来の枝刈りを引き継ぐため、あらゆる左文脈の全経路を保持する厳密探索ではない。

パスワード欄の入力スコープ判定とIME・学習の無効化は **TIP側のStage 3** の対象で、
今回のPython実装では行っていない。Windows TIPのビルド・実機検証も今回の対象外。

### 中断後に残った失敗の原因と修正

`test_context_bonus_flips_best_and_candidate_order` の固定時計では、左文脈「左」と「の」の
「か→乙」が同じタイムスタンプになる。`_index()` がその同値を先の記録で解決し、
仮想経路に古いPOS=1を載せていた。左文脈キー「の」は一致し、6000点のボーナスも
適用されていたが、「の」(RID=433)→POS=1の連接8238が、正しいPOS=1851への409より
7829高いため、1-bestが「？の甲」（2010点）のままだった。
文節候補は通常辞書のPOS=1851の経路にも文節全体のボーナスが効くため、修正前から「乙」が先頭だった。

`learning.py` の最新記録選択だけを修正し、時刻が同じならファイル順の最後を使う。
既存3項組の上書き時もその順序を更新する。正しいPOSでの「？の乙」は10点となり、
期待どおり1-bestになる。既存テストの期待値を保持し、候補先頭、同時刻での既存3項組の
再確定、別ストアでの再読み込み後のPOS選択も追加検証した。
設計の「最新記録」を同時刻について明確化した修正であり、ボーナス量・FSM・枝刈り・辞書コストは変更していない。
