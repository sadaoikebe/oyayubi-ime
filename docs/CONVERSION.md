# 変換の仕様（打鍵の判定・変換・候補・学習・LM）

変換エンジン（`yuragi/`）の中身の仕様。プロセスの構成・通信・置き場所は [REDESIGN.md](REDESIGN.md)、
キー操作の利用者向けの説明は [USAGE.md](USAGE.md)、評価のしかたは [EVALUATION.md](EVALUATION.md)。

```text
キー down/up + 時刻（TIP が付ける）
  → ChordFsm（同時打鍵の判定。yuragi/chord）
  → トークン列（Plain / AmbShift / ThumbTap / Literal）
  → トークン同期 Viterbi + Mozc OSS 辞書（yuragi/lattice）
  → ImeSession（composition・文節・候補・確定・学習。yuragi/ime/session.py）
```

---

## 1. 守ること

ノート PC の横長スペースバーでは、左右の親指キーを打ち分けられない。ゆらぎは、親指シフトの
**左右のあいまいさを残したまま変換に渡し**、辞書と文脈で左右を決める。

- **左右あいまいな打鍵を、1 本のひらがなに潰して既存 IME に渡さない。**「どうぞ」のような語が消える。
  左右を先に固定するフロント（やまぶきR・AutoHotkey・紅皿など）を置かないのも同じ理由。
- **同側を仮定しない。** 仮表示でも候補の仮定でも、同側固定はクロスで打つ濁音を日本語から消す。
- **あいまいさは左右だけ。** 近接キーの誤打など、左右以外のあいまいさを候補に出さない。
- **同時打鍵の判定は打鍵列の中で閉じる。** 判定のあとに残るのは左右のあいまいさだけ。
  英数／かなのモード推定と連動する判定はしない。
- **FSM の出力を後から書き換えない。** 同じキーだからといって `Plain(W)` を後続の `AmbShift(W)` に
  上書きすると、`か` のあと `え` で「か」が消える。トークンは一度出したら変えない。
- **かな配列と同時打鍵の判定規則は、NICOLA 配列規格書（日本語入力コンソーシアム）に基づいて自分で実装する。**
  既存の同時打鍵実装のソースは持ち込まない。
- 常用は US ANSI キーボード + NICOLA-A。JIS / NICOLA-J は品質の対象にしない。

> **注意（試して捨てた方式）**: 
> - あいまいな打鍵を 2^k 通りの読みに全展開すると、助詞が AmbShift になった時点で破綻する。
>   探索はトークン同期のまま行う（§4）。
> - 最初から E2E のニューラル変換にすると、打鍵に無い文を出せてしまう。LM は辞書と連接で作った候補の
>   並べ替えにだけ使う（§9）。
> - 単一のひらがな列を前提にした変換器（stock の `mozc_server`、Mozc の TIP のフォーク）は、
>   トークン列を受け取れないので使えない。

## 2. キーとトークン

### 2.1 配列

- 物理配列は US ANSI。仮想キーから NICOLA-A のキーへの対応は `yuragi/chord/keys.py`。
- かなの表は `data/nicola_a.json`（各キーの単独面・左親指面・右親指面）。
- 親指キーはスペースバー 1 本。左右は区別しない。

### 2.2 トークン

| トークン | 意味 |
|---|---|
| `Plain(key)` | 文字キー単独。単独面の文字 |
| `AmbShift(key)` | 文字キーと親指の同時打鍵。左右どちらの面かは決めない。`press`（押下の通し番号）と `turn`（その押下の中の順番）を持つ |
| `ThumbTap` | スペース単独。変換操作 |
| `Literal` | 数字・記号・Shift+英字など、変換しない 1 文字 |

### 2.3 リテラル面

- 辞書を引く読みの文字集合は **U+3041–U+3096（ぁ–ゖ）と U+30FC（ー）**。面の文字がこれ以外なら
  リテラル面とする（`yuragi/lattice/expand.py:is_literal_face()`）。1 コードポイントであること。
  > **注意**: この集合を Unicode の句読点カテゴリや「ひらがな以外」で決めない。句読点カテゴリでは
  > 数字・英字のリテラルと揃わず、「ひらがな以外」では「ー」が読みから落ちる。
- 句読点の単独面: Q =「。」、P =「，」（表示は「、」に正規化）、Z =「．」、/ =「・」。
- / の左親指面は「？」、右親指面は「ぉ」。Space + / は左右未確定の 1 トークンのままで、
  変換と文節候補で決める。Q・Z の右親指面、; の左親指面は空欄。
- 数字段と他の ANSI 記号に親指面は無い。数字・記号はリテラルで入り、Shift 時は US ANSI の文字が入る。
  かなのある OEM キーの単独面は NICOLA を優先する（`;` は「ん」）。

## 3. 同時打鍵の判定（`yuragi/chord/fsm.py`）

状態機械 S1〜S7 の表と各状態の出口は `fsm.py` 冒頭の説明が最新。要点:

- 定数: 判定の窓 `TIMEOUT_MS`（T）= 80ms、重なり `OVERLAP_MS`（V）= 20ms。
- 保留中の文字の期限は、その文字の down + T。張り直さない。
- 1 回の押下（Space の down から up まで）の最初の使い道は、同時打鍵か単独スペース（T を過ぎたら ThumbTap）。
- 押したままの間に打った文字（S7）は、出口で「Space との重なり」と「直前に離した文字の長さから見た残り」を
  比べて決める。文字が押下の中で離れたら同時打鍵。
- 単独スペースのあと、その押下の中で打った文字は単独として出す。
- 判定はキーの順序と時刻だけで 1 回だけ行う。出したトークンは変えない。

**同じ押下の中の親指打鍵は、左右が交互になる**（`yuragi/lattice/alternation.py`）。変換は押下ごとに
「1 番目の面が左か右か」だけを選ぶ。面が片側にしか無いキー（`;` Q Z）はその押下の向きを決める。
交互に読めない押下は、各打鍵が自分で面を選ぶ。`press` を持たないトークン（評価の読み、試験）は自由。
交互はペナルティではなく、破る経路は存在しない。

打鍵の時刻 `t` は、TIP がキーを処理するときに `QueryPerformanceCounter` から付けたミリ秒（TSF はキーの
時刻を渡さない）。エンジンはこの値を使うので、ブローカーの預かり時間の影響を受けない。

## 4. 変換（`yuragi/lattice/`）

- **トークン同期 Viterbi**（`token_viterbi.py`）: 各位置から、辞書にある読みの prefix だけを歩き、
  語の区間の上で Viterbi を取る。2^k の全読みは展開しない。コストは Mozc の単語コストと連接表。
- 1-best は位置ごとに右品詞の候補を `POS_KEEP`（12）まで残す（`decode_tokens`）。
  > **注意**: 1-best の枝刈りは品詞（RID）単位のままにする。読みの prefix 単位にすると 1-best の
  > 読み一致・表記一致が数ポイント落ちる。逆に RID 単位の枝刈りでは「既読にない／記憶にない」のような
  > 左右の対が落ちうるので、候補はこの枝刈りを使わない `nbest_tokens`（§8）と文節候補（§6.2）で出す。
  > コードのコメントの「WP0 §10/§13」はこの判断を指す。
- 辞書: Mozc OSS 辞書テキスト（`python -m tools.wp0.fetch_mozc_dict` で取得、
  `data/dictionary-manifest.json` の SHA-256 で照合）。全エントリを使い、読みごとに切り捨てない。
  語の長さは 16 トークンまで（`MAX_WORD_MORA`）。辞書に無い 1 文字は未知語アーク（`UNK_COST` = 12000）。
- 辞書キャッシュ（pickle）は無補正のまま保存する。名前は辞書マニフェストのハッシュ（REDESIGN §6.2）。
- **連接表の全 0 行**: 左品詞の連接行がすべて 0 なら、その行の全列（EOS を含む）に 3000 を足す。
  読み込みのたびに適用し、キャッシュには入れない。環境変数 `ZERO_ROW_PENALTY`（評価用。0 で無効）で
  値を変えられる。根拠と確認の記録は [ZERO_ROW_PENALTY.md](ZERO_ROW_PENALTY.md)。
- **リテラル**: リテラル面・明示リテラルは、表記＝読み＝その文字、単語コスト 0 の 1 トークンのアーク。
  リテラルへ入るときは直前のかな列を EOS で閉じ、次のかな列は BOS から始める。
  辞書の語も連接もリテラルを跨がない。空のかな列には BOS→EOS のコストを足さない。
- **辞書の重ね方**:
  - `data/user_lexicon.jsonl`: 手書きの補正辞書。評価条件の一部（Mozc/AJIMEE の数字はこれ込み）。
    > **注意**: 左右の違いで両方正しくなる語の対（既読／記憶）を、補正辞書のコストで片方に寄せない。
    > 既読を一律に安くすると「記憶にない」が「既読にない」に反転する。両方を候補に残すのが仕様。
  - `~/.yuragi-ime/personal_lexicon.jsonl`: 利用者の単語登録（`yuragi/ime/personal.py`、既定コスト 2600）。
    動いている IME にだけ重ね、評価には入れない。変換のたびにファイルの変化を見て、再起動なしで効く。
  - 学習履歴（§7）。評価には入れない。

## 5. セッションとキー操作（`yuragi/ime/session.py`）

### 5.1 入力と確定

- composition はトークン列の変換結果。打っている間も 1-best が下線つきで出る。
- 変換中に次の文字の down: 選択中の表示を確定し、新しい composition を始める。親指の押下は保持する。
- Enter: 未解決の打鍵も含めて全確定。
- Esc: 変換中は変換取消（元のトークンからの最良表示へ戻る）、入力中は破棄。
- BS: 変換中は変換取消だけ（トークンは残す）、入力中は末尾の 1 トークンを削除。
- 編集キーの up は何もしない。未解決の打鍵のあとにリテラルや編集キーが来たら、
  FSM の timeout 経路で先に解決してから処理する。
- Ctrl/Alt/Win 併用は素通し。Shift は US ANSI の大文字・記号として取り込む。
- キーの up と自動リピートで、候補操作を二重に行わない。

### 5.2 reset と直接入力

- `{"op":"reset"}`（フォーカス喪失、アプリが composition を打ち切った）: 確定を返さず、トークン・
  composition・候補・文節・FSM・タイマー・押下キー・修飾の追跡を捨てる。直接入力の設定は残す。
- 直接入力: 初期は `direct=false`。`set_direct`（true/false）と `toggle_direct`。状態が変わるときは
  未確定の composition・候補・保留中の打鍵を確定せずに捨てる（意図しない確定や学習をしない）。
  直接入力中の down/up は `pass_through:true` を返し、FSM にも composition にも渡さない。

### 5.3 キー操作（変換中）

| 操作 | 振る舞い |
|---|---|
| 最初の Space | 最初の非リテラル文節に注目して候補を開く |
| ← / → | 非リテラル文節の間を移動。両端で止まる |
| Space / ↓ / ↑ | 注目文節の次 / 次 / 前の候補。ページを越え、全候補の末尾・先頭で巡回 |
| PageDown / PageUp | 次 / 前の 9 件ページの先頭候補。範囲外では止まる |
| 1–9 | 表示中ページの行を選び、文節を固定する（確定はしない）。空行の番号は消費するだけ |
| 0 / Shift+数字 | リテラル入力。変換中なら表示を確定して次の入力へ |
| Shift+→ / Shift+← | 注目文節を 1 トークン伸ばす / 縮める（§6.4） |
| F6 / F7 | 注目文節をひらがな / カタカナに。続けて押すと、左右の読み違いの行へ順に進む |
| F8 | 注目文節を半角カタカナに |
| F9 / F10 | 打ったキーを全角 / 半角英数に。続けて押すと 小文字 → 大文字 → 先頭だけ大文字 |
| Shift+F6 | 注目候補の学習を忘れる（§7.4） |
| Shift+F7 | 直前の確定の学習を取り消す（§7.4） |
| 次の文字 / Enter | 全文節の表示を確定。文字なら新しい composition を始める |
| Esc / BS | 選択と候補を捨て、元のトークンからの最良表示へ戻す |

未変換の入力中の F6〜F10 は、変換してから同じ字種に変える。

### 5.4 推測変換（Tab、`yuragi/ime/predict.py`）

- 未変換の入力中に Tab を押すと、入力の末尾の続きの候補を通常の候補窓に出す。
  候補が無ければ Tab は素通し。打っている間は何も計算しない。
- 候補の出どころは 2 つ: 学習履歴の確定（読みの先頭 2 かなから。学習のボーナスと同じ順）と、
  辞書（先頭 3 かなから）。履歴が先、表記ごとに 1 行、最大 9 件。入力より長いものだけを出す。
- 続きは最大 8 かな。入力の末尾から、1-best の語境界の最後の 3 つのどれかで始まる最長の部分に付ける。
- 設定 `prediction`（`tab` 既定／`off`）。

## 6. 文節と候補（`yuragi/ime/bunsetsu.py`）

### 6.1 文節の区切り

最良経路の各**自立語**の頭で区切り、後続の助詞・助動詞などは直前の文節に付ける。
自立語は `id.def` の品詞で決める: 名詞・動詞・形容詞のうち接尾・非自立でないもの、
副詞・連体詞・接続詞・感動詞・接頭詞。先頭に付属語があれば、最初の自立語の直前も境界になる。
明示リテラルは独立した固定表示の区間で、文節移動では飛ばす。
あいまいなトークンのリテラル面（Space+/ の「？」など）が最良経路に入ったときは、前後と別の文節になるが
`literal=false` のままで、注目も選び直しもできる。学習の仮想経路（§7.3）も、それだけで 1 つの文節になる。

変換中に境界を自動では変えない。選んだ文節だけを置き換え、未操作の文節も自動で再変換しない。
隣の品詞が変わった文節は、再訪したときに新しい品詞で候補を採点し直す（表示は変えない）。
固定済みの表示が新しいコスト幅の外に出ても保持し、選択位置を `-1`（強調行なし）にする。

### 6.2 候補の探索

- 対象文節のトークン区間で、左右両面・全辞書エントリを使い、区間全体を覆う経路を列挙する。
  語の数や分け方を元の最良経路に合わせない。
- スコア = `T(左隣の末尾 RID, 最初の LID) + Σ単語コスト + Σ内部連接 + T(最後の RID, 右隣の先頭 LID)`。
  端とリテラルに接する側は BOS/EOS。
- 最良接尾コストの逆向き DP をポテンシャルにした A*。負のコストがあってもコスト順を保証する。
  同じ表記は最安の経路にまとめる。表示に要る分だけ遅延列挙する。
- **辞書候補の幅**: その区間・両隣の品詞での最良辞書経路 + `COST_WINDOW`（6000、等号を含む）。
  基準は実際の辞書語を少なくとも 1 つ含む最良経路。件数の上限は無い。
  > **注意**: 辞書候補を件数（上位 8 件など）で切らない。同音語の多い読みで、正しい表記まで落ちる。
- 辞書候補からは未知語アークを除く（単語コストが 12000 以上の実在エントリは除かない）。

### 6.3 候補の並び

1. 辞書候補（コスト順）。リテラル面だけで区間を覆う候補（`kind=literal`）は、そのまま 1 回だけ出す。
2. かな候補: その区間の**ありうる全読み**について、ひらがな・カタカナをこの順で。読みごとの最安経路の
   コスト順。幅も件数の上限も無い。辞書候補と同じ表記でも残す。左右のラベルは付けない。
3. 日付・時刻の書き方（`dates.py`、`kind=date`）: 「きょう」「らいねん」などの相対語に、今日の日付などを
   最後に足す（前の行の位置と番号を変えない）。時計に依るので学習しない。

数字の並びの文節は、別の候補列を持つ（`numbers.py`、`kind=number`）: 打った数字を先頭に残し、
漢数字などの書き方を続ける。どちらも 1-best の composition は変えない。

### 6.4 文節の伸縮

- Shift+→ は次の文節の先頭 1 トークンを取り込み、Shift+← は末尾 1 トークンを次の文節へ渡す。
- 1 トークンの文節は縮めない。末尾の文節は伸ばさない。伸ばして次の文節が空になったら消す。
  縮めて次の文節が無ければ、渡した 1 トークンで新しい文節を作る。明示リテラルの境界は跨がない。
- 区間が変わった 2 つの文節だけ候補を列挙し直し、先頭候補を出す（`fixed=false`）。右側を先に計算し、
  それを隣として注目文節を採点する。他の文節の選択・固定は保持する。注目位置は動かない。
- 伸縮した境界は、候補操作や左右の移動では元に戻らない。Esc / BS の変換取消、reset、直接入力への
  切り替えで捨てる。

## 7. 確定学習（`yuragi/ime/learning.py`）

ファイルの読み書き・整理・入切の設定は REDESIGN §6.7。

### 7.1 何を記録するか

Enter と「変換中に次の文字を打つ」自動確定の両方で、選択中の各文節を 1 行ずつ
`~/.yuragi-ime/learning.jsonl`（UTF-8 JSONL、追記だけ）に書く。候補を開く・巡回するだけ、
変換取消、未確定の reset では記録しない。リテラル自体は記録しない。

```json
{"reading":"こうせいを","surface":"校正を","left":"機関の","timestamp":1800000000.0,"cost":6305,"lid":1841,"rid":379,"user_word":false,"version":1,"record_id":"c048d12a722e420d8963016a3f242282"}
{"reading":"こうせいを","surface":"校正を","timestamp":1800000001.0,"version":1,"type":"suppress"}
{"record_ids":["c048d12a722e420d8963016a3f242282"],"timestamp":1800000002.0,"version":1,"type":"tombstone"}
```

- 確定（`type` 省略）: `reading/surface/left` は文節全体の読み・表記・直前の文節の表記。`timestamp` は
  Unix 秒。`cost` は学習ボーナスと両隣への連接を含まない文節内部のコスト（内部の語間の連接は含む）。
  `lid/rid` は両端の品詞。`user_word` はかな確定からの自動登録。`record_id` は UUID（無い古い記録も読む）。
- 左隣: composition の先頭では、直前に確定した最後の区間の表記を引き継ぐ。リテラルのあとは
  その表記。reset で空に戻す。アプリの周辺テキストは読まない。
- 意味はファイル順の再生で決まる: tombstone が指す確定を除き、各（読み, 表記, 左隣）について、
  その組（読み, 表記）の最後の抑制より後の最新の確定が有効。時計が戻ってもファイル順を優先し、
  `timestamp` は減衰にだけ使う。
- 壊れた行・途中で切れた最終行・知らない形式は無視する。ローカルの平文で、どこにも送らない。

### 7.2 ボーナス

学習点は辞書・連接のコストとは別に引く。記録 r の重み
`w(r) = 2 ** (-max(0, 現在時刻 - r.timestamp) / 30日)`。

| 一致 | 減算値 |
|---|---|
| 同じ（読み, 表記） | `2400 × その組の最新記録の重み`（`PAIR_BONUS`） |
| 左隣の表記も一致 | 上に加えて `3600 × その 3 項組の最新記録の重み`（`CONTEXT_BONUS`） |

- 直後は 2400、同じ左隣なら 6000、30 日で半分。頻度は足さず最新値を使うので、同じものを何回確定しても
  6000 を超えない。
- 1 回の変換・候補生成の間は、学習内容と現在時刻のスナップショットを固定する。

### 7.3 変換への効き方

- 確定した既知の文節は、内部コストと両端の品詞を保った**仮想の経路**として格子に載せる
  （複数語にまたがる学習を単語に分解して失わないため）。元の辞書経路も残す。
- **未知語の自動登録**: かな候補の（読み, 表記）が辞書にも補正辞書にも無ければ、`user_word=true`、
  一般名詞の品詞（1851）、コスト 6000（`USER_WORD_COST`）で登録する。ひらがな・カタカナとも
  ひらがなの読みで登録する。16 トークンを超える語も扱う。リテラル面を読みとして通さない。
- 1-best: 仮想経路を通るときに、その時点の左隣を使ったボーナスを引く。
- 文節候補: 完成した区間全体の（読み, 表記, 左隣）にボーナスを適用して並べる。A* の未完成経路には
  最大ボーナス 6000 を引いた下限を使う。辞書候補の幅 6000 は保ち、かな候補は末尾に残す。
- 評価（`load_lex()`、`decode_tokens` の既定、`nbest_tokens`）は学習を読まない。

### 7.4 忘れる・取り消す

- **Shift+F6（忘れる）**: 注目行の（読み, 表記）を全左隣で抑制する（`suppress` を追記）。注目文節だけを
  採点し直して先頭を選ぶ。他の文節の選択・固定・伸縮した境界は保持する。改めて選んで確定すれば、
  新しい学習として効く。通常辞書・補正辞書の候補とかな候補は残る。候補表示が無い・リテラル候補では何もしない。
- **Shift+F7（取り消す）**: このセッションで記録できた直近の確定の全文節を 1 組として取り消す
  （`tombstone` を追記）。繰り返すと確定ごとに遡る。同じ組の以前の学習が残っていれば、その減衰した
  ボーナスに戻る。確定した文字は変えない。リテラルだけの確定・取消・reset・忘却は積まない。
  履歴はセッションのメモリにあり、reset を跨ぐが、エンジンの再起動や他のセッションの確定は遡らない。
  書けなかったときは履歴を消費しない。
- 学習が `paused` なら新しく記録しない（覚えた内容は使う）。`off` なら読みも書きもしない。

## 8. n-best（`nbest_tokens`、評価と LM 用）

`nbest_tokens(tokens, lex, k=8) -> (list[DecodeResult], stats)`:

- 表記ごとに最安の経路を 1 件、スコアの非減少順に返す。k 件か、対象の全表記を出したら終わる。
  `k <= 0` は空。入力が空なら、空表記・コスト 0 の 1 件。
- 前向きの厳密 Viterbi（打ち切りなし）で各位置・品詞の最小コストを求め、EOS から後ろ向き A*。
  同じ（開始位置, 先頭 LID, 後ろ側の表記）は最安だけを残す。スコア幅・pop 数・件数の内部上限は無い。
- 未知語アークと、語コストが `UNK_COST` 以上の語は含めない（この条件を満たす経路の中での真の k-best）。
- 学習を読まない。リテラルの境界には `BOUNDARY_RID=-1` を使う。

## 9. LM による並べ替え（`yuragi/ime/lm_rescore.py`、`lm_async.py`）

- Space で変換するときだけ、かなの区間ごとに「学習込みの 1-best（先頭）+ `nbest_tokens` の k-best」
  （重複を除いて最大 k 件）を因果 LM で採点し直す。打っている間・未変換の表示は Viterbi の 1-best のまま。
- `score = (候補のコスト − 1-best のコスト) + α × 500 × NLL`（NLL は左文脈を条件にした候補の負の対数尤度、自然対数）。
  最小を選び、同点なら 1-best を残す。
- 既定: モデル `rinna/japanese-gpt2-small`（インストール時に固定リビジョンで取得）、α = 1.0、k = 8。
  エンジンでは既定で使う（設定 `lm_rescore` で切れる）。読めなければ LM なしで動く（REDESIGN §6.2）。
- 左文脈: その接続で確定した文字列。800 字（`CONTEXT_CHARS` の 4 倍）を超えたら最後の 200 字に切り詰める
  （採点に使うのは下の窓の分だけなので、結果は変わらない）。Enter の確定では保つ。
  reset、トークンが無いときの Ctrl/Alt/Win、キャレットが動きうるキー（矢印・Home・Tab など）で消す。
  Backspace は末尾を 1 字削る。アプリの文書は読まない。
- 採点は厳密（近似しない）: 左文脈の KV キャッシュを全候補で使い回し、続きなら差分だけ通す。窓は
  最後の 48〜127 トークンで、開始位置を決まった刻みでだけ動かす（キャッシュの状態でスコアが変わらない）。
  （左文脈, 候補）ごとに覚える。
  > **注意**: Transformer のブロックを手で駆動しない。transformers の版が上がって引数が消えたとき
  > （GPT2Block の `layer_past`、4.57）、左文脈なしで採点しているのに気づけなかった。
  > モデル・トークナイザ・キャッシュの公開 API だけを使う。
- **打鍵の経路から外す**（エンジンだけ）: LM は専用のワーカースレッドで動く。変換の要求は最大
  `GRACE_MS`（30ms）だけ待ち、間に合わなければ表示を変えずに `pending:true` を返す。待っている間に
  届いたキーは順に溜め、変換が決まってから届いた順に再生する（変換が決まったあとの処理は、同期で
  動かしたときと同じ）。変換は LM の結果で決めるが、次のどれかのときは Viterbi の 1-best で決める:
  `DEADLINE_MS`（400ms）を過ぎた、溜めたキーが `MAX_QUEUE`（512）を超えた、LM のワーカーが
  `STALL_MS`（5 秒）以上ひとつの採点から戻らない、LM が使えない。つまり PC が重いと、同じ打鍵でも
  LM なしの結果になることがある。親指の押下から `PREFETCH_DELAY_MS`（30ms）で先読みを始める
  （設定 `lm_prefetch`: `thumb` 既定／`typing`／`off`）。
- LM が `MAX_ERRORS`（3）回続けて失敗したら、エンジンを起動し直すまで LM を使わず、注意 `lm` を出す。
- LM を待っている間に `reset`・`set_direct`・`toggle_direct` が来たら、その変換と溜めたキーを捨てる
  （未変換の入力は残る）。直接入力のモードが実際には変わらなかった場合も捨てるので、同期で動かした
  ときと結果が違う。TIP が `set_direct` を送るのはエンジンにつなぎ直した直後だけ（REDESIGN §5.6）。

## 10. 返事の項目

エンジン（`yuragi/ime/server.py:snapshot`）の返事。ブローカーはこれに `seq` を付けて TIP に返す
（REDESIGN §5.5）。受け取る側は知らない項目を無視する。

| 項目 | 中身 |
|---|---|
| `composition` / `commit` | 変換中の表示 / この要求で確定した文字 |
| `converted` | 候補を開いた変換中か |
| `direct` / `pass_through` | 直接入力か / この down・up をアプリに渡すか |
| `fsm` / `n_tokens` / `timer` | FSM の状態 / トークン数 / 次に `timeout` を送る時刻（無ければ null） |
| `segments` | 各文節・リテラルの `start/end`（トークン位置）、`surface/reading`、`literal/fixed`、`display_start/display_end`（表示のコードポイント位置。TIP が UTF-16 の位置に直す）。半開区間 |
| `focus` | 注目文節の `segments` 内の位置。無ければ -1 |
| `candidates` / `cand_index` / `candidate_kinds` | 注目文節の現在のページ（最大 9 件）/ ページ内の選択位置（無ければ -1）/ 各候補の `dictionary`・`kana`・`literal` など |
| `candidate_page` / `has_next_page` | 0 始まりのページ / 次のページの有無 |
| `predicting` | 候補窓が推測変換の候補か |
| `pending` | LM を待っていて、表示はまだ変わっていない（§9） |

要求の `op` は `down` `up` `timeout` `reset` `set_direct`（`direct` は JSON の真偽値）`toggle_direct` と、
`context`（`{"op":"context","text":…}`。LM の左文脈を `text` の最後の 200 字にする。TIP は使わない。評価と試験用）。
キー要求の `mods` は小文字名の配列（`["shift","ctrl","alt","win"]` の部分集合）。省略したら修飾キー自体の
down/up で追跡する。

## 11. 設定

`~/.yuragi-ime/config.json` に、エンジンの引数と同じ名前（`lm_deadline_ms` など）で書く。
コマンドラインの引数が最優先、次にファイル、無ければ既定値。読むのはエンジンの起動時。
全項目と今の値は `python -m yuragi.ime.manage config show` か、設定ウィンドウの「設定」タブで見られる。
書き換えは `manage config set` / `unset` か設定ウィンドウで、どちらもエンジンの引数と同じ変換・検査を通し、
知らないキーは残し、一時ファイルに書いてから置き換える。反映はエンジンの起動し直し（`manage server restart`
か設定ウィンドウの「変換エンジンを再起動」）で。
主な項目: `learning`（on/paused/off）、`prediction`（tab/off）、`lm_rescore`（true/false）。

TIP の設定は別のファイル `~/.yuragi-ime/tip.json`（切り替えキー `toggle_vk` `toggle_mods`、ログ `log` `log_text`。
[src/tip/README.md](../src/tip/README.md)）。
